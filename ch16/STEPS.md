## 练习1：带参宏（12.1 宏定义）

### 目标
亲手感受「宏是文本替换」带来的括号陷阱和副作用，建立肌肉记忆。

### 你要写什么
1. 定义两个宏（放 main.c 顶部，或单独 `macro.h` 再 include）：
   - `SQR(x)` 求平方：**先写一个错误版**（参数和整体都不加括号），**再写一个正确版**（双括号）。
   - `MAX3(a,b,c)` 返回三者最大值。
2. 在 main 里做对比测试：
   - 错误版 `SQR(a+1)`（a=3）：看输出是不是你以为的 16。
   - 正确版 `SQR(a+1)`：确认输出 16。
   - `SQR(++i)`（i 初值 1）：看 i 最后变成多少。
   - `MAX3(a+b, a*b, a-b)`：嵌套调用，确认结果对手算。

### 验收输出（自己核对）
- 错误版 `SQR(3+1)` 展开为 `3+1*3+1 = 7`（不是 16）→ 这就是坑。
- 正确版 `SQR(3+1)` = 16。
- `SQR(++i)` 之后 i 比预期多 1（如 1→3）→ 宏别传带副作用的表达式。
- `MAX3` 嵌套结果符合手算。

### 坑预警（写完补进 BUG.md）
在 `BUG.md` 的「待补区」新增一条：
- 带参宏必须 `((x)*(x))` 双括号（参数括号 + 整体括号）。
- 宏里别传 `++i`、`i++` 这类有副作用的表达式。

## 练习2：多源文件（12.2，预演 M2）

### 目标
把「一个文件搞定」改造成「头文件 + 实现文件 + 主文件」，并亲手 `gcc` 编译链接，理解分文件。

### 你要写什么（三个文件）
挑 ch7 或 ch10 一个旧练习，例如「数组求最大值」或「指针遍历求和」，拆成：
- `calc.h`：放函数原型 + 头文件守卫。
  - 守卫写法：`#ifndef CALC_H` / `#define CALC_H` / ... / `#endif`（或 `#pragma once`）。
  - 例：`int array_max(int arr[], int n);`
- `calc.c`：放函数实现（`#include "calc.h"` 后写函数体）。
- `main.c`：`#include "calc.h"`，在 main 里准备数据、调用、打印。

### 编译命令（亲手敲，别用 IDE 一键）
- `gcc main.c calc.c -o app`
- 运行：Windows 下 `app.exe`（或 `./app`）

### 验收
- 三文件分别存在，`gcc` 一条命令编出 `app` 并正确运行。
- **主动试错**：故意删掉 `calc.h` 的守卫，再把 `calc.h` 在 `main.c` 里 `#include` 两次，看报什么错（重声明 / 重复定义）→ 理解守卫为什么必须有。

### 坑预警
- 函数**实现**别放 `.h`（多个 `.c` 包含会重复定义）。
- `#include "calc.h"` 用双引号（本地头文件），不是 `<>`（系统头文件）。
- `calc.c` 也要 `#include "calc.h"`，养成习惯。
